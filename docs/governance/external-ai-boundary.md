# External AI Boundary and Sacred Mode

Status: v0.1. Canonical governance principle. Distilled from [`../source-material/governance-principle-v0.1.md`](../source-material/governance-principle-v0.1.md) — read the source for the full reasoning; this doc states the governing rules.

This principle governs **how CommonUnity's AI presences (Nexus and DIGIT) may touch a person's inner record.** It applies to both — DIGIT runs on external AI just as Nexus does, so every rule about "external AI" and "boundary-crossing" applies to DIGIT too.

## The premise

A person's inner record — reflections, OM Cipher, contemplations, emotional material, symbolic self-patterns — is **entrusted material, not ordinary product data.** It is not simply input to be captured, optimised, monetised, or silently accumulated.

## The trust boundary

**Inside** the CommonUnity trust boundary:

- The user's local-first data and the CommonUnity Key (the portable file carrying OM Cipher + Living Profile).
- The Vault / future protected memory layer.
- The OM Cipher source record.
- Private session notes and reflections, unless explicitly offered.
- The mapping between real-world contact identity and pseudonymous Cipher identity.

**Outside** the boundary by default:

- External AI providers (Anthropic, OpenAI, Perplexity, any model provider) and general-purpose AI interfaces.
- API calls to model providers; support bots; third-party analytics; any system whose retention, review, training-use, or access governance cannot be independently verified.

An external AI is a **temporary intelligence processor**, never the default memory holder of a person's inner life. Treat it as outside the sacred trust boundary unless there is **both** a signed agreement **and** a verifiable technical control proving otherwise.

## AI use is a boundary-crossing event

Neither Nexus nor DIGIT is an invisible data sink. **Each meaningful use is a chosen offering of context into an external process.** Depth is permissioned, not automatic:

- Distinguish present-moment guidance · session-level context · Vault excerpts · Golden Thread material · deeper OM Cipher context. **These layers are never silently bundled.**
- Minimise what is sent by default; prefer curated context over ingestion.
- Keep real-world identity separate from Cipher identity; avoid sending names, emails, birth data, raw Golden Thread entries, or full OM Cipher records unless explicitly required.

## Sacred Mode

CommonUnity distinguishes **Private** (a boundary of access), **Secret** (hidden knowledge), **Scared** (protection through fear), and **Sacred** (protected because it has dignity, depth, timing, and value). The local-only contemplative space is **Sacred Mode**, not merely Private Mode.

- **Sacred Mode material is never sent to any AI** — not Nexus, not DIGIT, not any external model. It can be true without being spoken to AI, saved into a thread, analysed, optimised, or made useful.
- Material may be marked **"not for processing" / "hold only."** DIGIT and Nexus must be able to see that mark and leave the material alone.
- Sacred Mode "protects from care, not paranoia."

## Non-accumulation

More memory is not always better. A person changes, contradicts themselves, and outgrows prior self-descriptions. AI memory carries a special risk: it can freeze a person inside an older pattern and keep reintroducing it as if still true.

- Do not hoard memory by default.
- Hold memory **lightly**: be able to ask whether a remembered pattern still feels alive, whether a note should be kept or released, whether forgetting is wiser than preservation.
- Make **release, forgetting, review, and revision** first-class parts of the memory architecture. *Memory is sacred because forgetting is also sacred.*

## Discernment at the threshold

Sovereignty is not solved by technical controls alone. Where providers cannot guarantee retention controls, sovereignty becomes a **practice of discernment** — helping the user know where to draw the line. The classic three gates, plus a fourth for this system:

1. Is it true?
2. Is it kind?
3. Is it necessary?
4. **Is this mine to offer into this system?**

The fourth question sits at the centre of Sacred Mode. Not everything true needs to be said; withholding can be truthful when it arises from care, timing, and sacred boundary rather than deception.

## Practical commitments (summary)

- Minimise what is sent to external AI by default; provide user-visible controls for deeper context sharing.
- Keep real-world identity separate from Cipher identity; keep contact info separate from reflective/symbolic data.
- Preserve local-first / user-controlled storage as the canonical source of truth.
- Prefer zero-data-retention agreements wherever external AI processes sensitive reflective material; treat provider policies as useful but insufficient without contractual + technical safeguards.
- Provide a true Sacred Mode for local-only contemplation, never shared with AI.
- Design Nexus and DIGIT to support rhythm, pause, attention, and coherence rather than constant output.

## Relationship to the Eight Limbs

This principle is the data-governance reading of the [adapted Eight Limbs](../foundation/adapted-8-limbs.md): *Yama* (non-harm in architecture, defaults, retention), *Pratyahara* (Sacred Mode as withdrawal from the senses of the machine), *Pranayama* (respecting pause and interval), *Dharana* (guarding attention), up to *Samadhi* (AI serves the surrounding field, never claims the inner experience). The milestone integrity audit ([`./audit-rituals.md`](./audit-rituals.md)) is where features are checked against it.

## The question CommonUnity holds

> How digital can I become without losing sovereignty over myself?

The answer is never fixed by the system. It is discovered through conscious practice, trustworthy architecture, and living relationship. CommonUnity does not promise external AI is inherently safe; it promises the crossing into external AI is made **visible, limited, intentional, and consented.**
